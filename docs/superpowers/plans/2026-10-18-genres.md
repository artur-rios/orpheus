# Browse, play and search by genre — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A **Genres** tab that lists every genre, opens one onto its artists, records and songs, and plays only the
tracks tagged with it — and a search selector for song, artist, album, genre or all (UC-36, and UC-12 widened).

**Architecture:** The catalog starts keeping every genre a file holds (split at `;`, `|`, `,`, never `/`; MP3 genres read
from the `TCON` frame directly). Pure functions in `music_grouping.dart` build a genre's *library* — every whole record
with a track in it — so the Music tab's browser can be reused inside a genre unchanged: the browser is lifted out of
`MusicLibraryView` into a `MusicBrowser` that takes its state, its entries and a `MusicNavigator`, and an inherited
`MusicScope` tells the rows which navigator to drive and which entries to gather a queue from. A
`GenreBrowseController` holds the Genres tab's own place.

**Tech Stack:** Flutter, Dart 3, flutter_riverpod 3, audio_metadata_reader 1.8.0, gen-l10n (en + pt), flutter_test.

**Spec:** `docs/superpowers/specs/2026-10-18-genres-design.md` (its numbered "calls" are referred to as *call N*).

## Global Constraints

- Branch: `feature/genres` (exists; the spec is committed on it). Pull request into `develop`.
- Genre separators are exactly `;`, `|` and `,`. `/` is **never** a separator — *Hip-Hop/Rap* is one genre, in every
  format, MP3 included.
- Genres match by `genreKey`: trimmed, lower-cased. The name shown is the spelling most tracks in the library use; on a
  tie, the one that sorts first by `byName`, then by plain `compareTo`.
- `null` genre key means *No genre* (a track with no genres), exactly as a `null` artist means the untagged artist.
- Browsing is by record (a record listed under every genre its tracks carry, opened whole); playing a genre is by track
  (only tracks tagged with it). An artist's untitled group (no album name) is not a record: under a genre it holds only
  its tracks in that genre (call 13).
- The Music tab's behavior, ordering, queues and back gesture must not change. Every existing test stays green
  untouched, except where a task says it edits one.
- Every user-visible string goes in both `lib/core/l10n/app_en.arb` and `lib/core/l10n/app_pt.arb` with an `@key`
  `description`; regenerate with `flutter gen-l10n`; the generated files in `lib/core/l10n/generated/` are committed.
- Test names follow `GivenX_WhenY_ThenZ`. Fixtures come from `test/support/` (`entry(...)`, `Harness`, `pumpHarness`,
  `id3Tag`/`frame`/`encodedText`, `taggedFlac`).
- Every task ends green on `flutter analyze`, `dart format --set-exit-if-changed lib test`, and its tests.
- Commits: lowercase Conventional Commits, subject ≤ 50 characters, body wrapped at 72, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Code comments match the codebase's voice: a doc comment on every public member, explaining *why*.

## Review Focus

1. **A library scanned by 1.4.0** (catalog document version 1, a `genre` string per row) → refused and re-scanned once,
   never half-read into an entry with no genres (pinned in Task 3).
2. **Separators with nothing between them — `Rock;`, `; Pop`, `Rock;;Pop`, `,`, `   `** → no empty or blank genre, and
   no *No genre* membership for a track that does name one (pinned in Task 1).
3. **ID3 genre frames as real taggers write them:** v2.4 UTF-16 with a BOM per value, v2.3 `(17)`, `(17)(18)`,
   `(17)Rock & Roll`, `(RX)`, a bare `17`, and a code outside the table → readable names, nothing numeric leaks into the
   genres list (pinned in Task 2).
4. **One track tagged `Rock; rock; ROCK `** → one genre, its plays counted once in the statistics, listed once
   (pinned in Tasks 1 and 5).
5. **The search selector on a 411-pixel phone in Portuguese** → every segment reachable by scrolling sideways, no
   wrapped or clipped labels and no overflow error (pinned in Task 10).

### Task 2: Every genre in an MP3's genre frame

The tag library stops an ID3v2.4 `TCON` at its first zero byte and splits at `/`, so the scan reads the frame itself.
The read-only frame walker already exists in the lyrics reader (it covers v2.2–2.4, unsynchronisation, extended
headers and data-length indicators); this task moves it where the library can use it. *(The spec suggested reusing the
tag editor's `_textValues`; the lyrics walker is the read-only one and covers more versions, so the editor is left
alone.)*

**Files:**
- Create: `lib/features/library/data/id3v2_frames.dart`
- Create: `lib/features/library/data/id3_genres.dart`
- Modify: `lib/features/lyrics/data/id3_synced_lyrics.dart` (remove `_Frame`, `_Id3Tag`, `id3HeaderLength`,
  `id3TagLengthOf`, `_bigEndian`, `_syncSafe`, `_deUnsynchronise`, `_withoutExtendedHeader`; import the new file)
- Test: `test/features/library/data/id3_genres_test.dart`
- Test (must stay green, unedited): `test/features/lyrics/data/id3_synced_lyrics_test.dart`,
  `test/features/lyrics/data/file_lyrics_source_test.dart`

**Interfaces:**
- Produces, in `id3v2_frames.dart` (moved code, made public, behavior unchanged):
  - `const int id3HeaderLength = 10;` and `int? id3TagLengthOf(Uint8List header)`
  - `class Id3Frame { const Id3Frame(this.id, this.data); final String id; final Uint8List data; }`
  - `class Id3v2Tag { final int major; final Uint8List body; static Id3v2Tag? of(Uint8List bytes); Iterable<Id3Frame> frames(); }`
  - new: `List<String> id3TextValues(Uint8List data)` — a text frame's values: first byte is the encoding (0 Latin-1,
    1 UTF-16 with BOM, 2 UTF-16BE, 3 UTF-8; anything else read as Latin-1), split at that encoding's terminator (one
    zero byte, or a zero 16-bit unit), empty values dropped. Lenient: malformed bytes are replaced, never thrown.
  - new: `Uint8List? readId3v2Tag(File file)` — synchronous: reads `id3HeaderLength` bytes, asks `id3TagLengthOf`,
    returns that many bytes from the start (never past the end of the file), or `null` where there is no tag.
- `id3_synced_lyrics.dart` keeps its public API: `export '../../library/data/id3v2_frames.dart' show id3HeaderLength, id3TagLengthOf;`
- Produces, in `id3_genres.dart`: `List<String>? id3GenreValues(Uint8List tag)` — the values of every `TCON` (v2.3,
  v2.4) or `TCO` (v2.2) frame, in order, each resolved; `null` where `Id3v2Tag.of` finds no tag or no such frame.
  Resolution of one value:
  - `^\d+$` → the ID3v1 table name for that code; dropped when the code is not in the table;
  - `^((\(\d+\)|\(RX\)|\(CR\))+)(.*)$` → the trailing text when it is not blank (`(17)Rock & Roll` → `Rock & Roll`),
    otherwise each reference in turn: a code → its table name, `(RX)` → `Remix`, `(CR)` → `Cover`;
  - `((` at the start → the value with one `(` removed (ID3v2.3's escape);
  - anything else → itself.
  The table is `id3GenreName(int)` from `package:audio_metadata_reader/src/constants/id3_genres.dart`, imported with
  `// ignore: implementation_imports` and a comment saying why (the package does not export it; copying 192 names would
  drift from the reader's own).
